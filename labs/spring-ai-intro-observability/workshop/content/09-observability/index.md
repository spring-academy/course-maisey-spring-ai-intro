## Enable Actuator Metrics

Expose the metrics and Prometheus endpoints via Spring Boot Actuator:

```editor:select-matching-text
file: ~/sample-app/src/main/resources/application.yaml
text: "spring:"
description: Expose actuator endpoints
before: 0
after: 0
cascade: true
```

```editor:replace-text-selection
file: ~/sample-app/src/main/resources/application.yaml
hidden: true
text: |
  management:
    endpoints:
      web:
        exposure:
          include: health, metrics, prometheus
  spring:
```

## Inspect AI-Specific Metrics

List all available Spring AI metrics:

```execute
curl -s localhost:8080/actuator/metrics | jq '.names | map(select(startswith("gen_ai")))'
```

You should see `gen_ai.client.token.usage` and `gen_ai.client.operation.duration`.

Inspect token usage in detail:

```execute
curl -s localhost:8080/actuator/metrics/gen_ai.client.token.usage | jq
```

The response breaks down `input` tokens (sent to the model) and `output` tokens (generated by the model). These are the numbers that determine cost.

Inspect call latency:

```execute
curl -s localhost:8080/actuator/metrics/gen_ai.client.operation.duration | jq
```

This shows the distribution of end-to-end call durations for every AI request made since startup.

## View the Raw Prometheus Output

```execute
curl -s localhost:8080/actuator/prometheus | grep gen_ai
```

This is what a Prometheus scraper would collect. Each metric is tagged with attributes such as `ai.operation.name`, `ai.provider`, and `gen_ai.system` so you can filter by operation type in dashboards.

## Set a Token Limit

Prevent runaway costs by capping the maximum number of output tokens:

```editor:select-matching-text
file: ~/sample-app/src/main/resources/application-openai.yaml
text: "model: gpt-4o"
description: Add max token limit
before: 0
after: 0
cascade: true
```

```editor:replace-text-selection
file: ~/sample-app/src/main/resources/application-openai.yaml
hidden: true
text: |2
            model: gpt-4o
            max-tokens: 1000
```
